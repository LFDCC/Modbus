## #43 续（闭环）：slave 真实链路验收 + 字节序修复 — 冒烟测试后追加
- **前置纠正（本日志 line 47 有误，以此为准）**：TCP 从站适配器**不能**用 `SetSingleStreamDataHandlingAdapter` 配置 `TcpService`——它会把适配器挂在 service 自身而非每个 accepted session，导致 `PreviewReceivedAsync` **永远不触发**（曾用字节探测确认），slave 收不到请求、master 挂起。正确做法是用 `SetTcpDataHandlingAdapter(() => new ModbusTcpRequestAdapter(Default))`（虽 Obsolete CS0618，但**唯一能向 session 传播**的入口），在 `ModbusFactory.CreateTcpSlaveNetworkAsync` 内 `#pragma warning disable CS0618` 抑制。UDP 仍用 `SetUdpDataHandlingAdapter`（未过时）。MEMORY.md 对应条目已同步修正。
- **为什么 252 单测发现不了 slave 链路 bug**：单测不覆盖真实 socket 成帧。本会话搭了临时 loopback 冒烟工程（`CreateTcpSlaveNetworkAsync`+`CreateTcpMasterAsync`，5 检查），发现 4/5 通过、WriteSingle 失败。
- **根因（字节序）**：`TouchSocketBitConverter.Default` 是**小端**，而 Modbus PDU/MBAP 全是大端（网络序）。修复三处 little-endian 误用：
  1. `ModbusRequest.SetValue(ushort)`/`SetValue(short)` 原 `Default.GetBytes` → 改 `BigEndian.GetBytes`（master 发 FC06 写值 999 原成 `E7 03`→59139，现 `03 E7`）。**（这是 WriteSingle 失败根因。）**
  2. `ModbusTcpRequestParser`/`ModbusTcpResponseParser` 的 MBAP 头（length/txId/protocolId）原 `Default` 小端读 → 改 `BinaryPrimitives.ReadUInt16BigEndian`（修复 master 真实响应解析）。
  3. 5 个功能码 handler 的 `ParseRequest/ResponsePdu` 内 `*.To<ushort>` 元数据读全改 `BigEndian`（仅影响 `ModbusRequestData/ResponseData` 的 StartingAddress/Quantity，字节载荷 `Data` 始终原始 wire 字节、被 `Reconstruct` 直接拷贝，不影响线上字节）。
- **CRC 必须仍用 `Default`（小端）**：Modbus CRC 低字节在前，`TouchSocketModbusUtility.cs:109` 不改。
- **验收（修复后）**：冒烟 5/5 PASS；`slave.log` 字节级确认 `0106000203E7`（999 大端），回显与 FC03 读回均为 `03E7`。`dotnet build . -c Release` 0 错误；`dotnet test NModbus.UnitTests -c Release --no-build` 252 通过/0 失败。临时冒烟/探测工程已删除（在 %TEMP%）。
