## per-call timeout 重构（撤销之前删 timeout 参数的决定）
- 用户决定：`CancellationToken` 语义不变（外部/全局取消，如 while 循环控制）；超时改为 **per-call `timeout` 参数**，**取代 `engine.Timeout` 属性**。用户原话：“这个timeout用来替代engine.timeout”。
- 确认设计（AskUserQuestion 选 A）：移除 `engine.Timeout`；每个读写/诊断方法两个重载——`Method(..., CancellationToken ct=default)` 无超时 + `Method(..., int timeout, CancellationToken ct=default)` per-call 超时。无超时重载以 `timeout:0` 委托带超时重载。
- C# 硬约束：单签名 `Method(int timeout=0, CancellationToken ct=default)` 会让 `read(cts.Token)` 把 token 绑到 int 报错 → 必须两个重载才能让 `read(cts.Token)` 和 `read(2000, cts.Token)` 都位置调用（原版 TouchSocketModbus 也是两重载）。
- 改动：
  - `IModbusClientEngine`：删 `int Timeout { get; set; }`；`SendModbusRequestAsync` 签名改 `(ModbusRequest request, int timeout = 0, CancellationToken cancellationToken = default)`。
  - 6 引擎：删 `public int Timeout { get; set; }`；公开 wrapper 用传入 `timeout`（不再 `this.Timeout`），Core 不变。
  - `IModbusClient` / `ModbusClient`：14 个读写/诊断方法各加 with-timeout 重载（无超时重载委托 `timeout:0`）；`BroadcastWriteSingleRegisterAsync` 不读响应、无超时重载。`ReturnQueryDataAsync`/`ReadBasicDeviceIdentificationAsync` 的 with-timeout 重载转发 timeout 给被调方法。
  - `IConcurrentModbusClient` / `ConcurrentModbusClient` / `RegisterFunctions` / `EnronModbus` / 示例 / 测试：**未改**——都用 `cancellationToken:` 命名或位置传 token，绑定到无超时重载，不受影响。
  - README“超时与取消”小节重写为 per-call timeout 设计；`Modbus.cs` 删过期注释 `//public const int DefaultTimeout = 1000;`。
- 行为：`timeout <= 0`（默认）→ 仅 ct 控制取消，无超时；`timeout > 0` → `CTS(timeout)` + linked(ct)，OR 链接，超时抛 `TimeoutException`、ct 取消抛 `OperationCanceledException`。超时覆盖信号量排队+发送+等待；不关 socket、不打断在途发送、迟到响应丢弃（沿用上一轮 Core 结构）。
- 验证：`dotnet build` 0 警告/0 错误；`dotnet test` 58 通过。
- 当前超时 API 全貌：`client.ReadXxx(..., cts.Token)` 无超时循环用；`client.ReadXxx(..., 2000, cts.Token)` 单次 2 秒超时。无 `engine.Timeout`。

## 引擎加 ConnectTimeout + ReadWriteTimeout（per-call 覆盖回退）
- 用户决定（AskUserQuestion）：engine 加 `ConnectTimeout`（连接超时，默认 0=不限制）+ `ReadWriteTimeout`（读写默认超时，默认 0）。per-call `timeout>0` 覆盖 `ReadWriteTimeout`；`timeout<=0` 回退 `ReadWriteTimeout`（并存，非撤销 per-call）。
- 改动：
  - `IModbusClientEngine`：加 `int ConnectTimeout { get; set; }` + `int ReadWriteTimeout { get; set; }`，更新 `SendModbusRequestAsync` 文档说明回退。
  - 6 引擎：加两个属性（在 IsConnected 前）；`SendModbusRequestAsync` wrapper 加 `int effectiveTimeout = timeout > 0 ? timeout : this.ReadWriteTimeout;` 用 effective 替代 timeout；`ConnectAsync` 改 async + 用 `ConnectTimeout` 包（`<=0` 直连；`>0` 建 `CTS(ConnectTimeout)`+linked，catch OCE 转 `TimeoutException("The Modbus connection attempt has timed out.")`）。TCP/RtuOverTcp 包 `TcpConnectAsync`；RTU/ASCII 包 `SerialPortConnectAsync`；UDP/RtuOverUdp 包 `StartAsync`+m_online。
  - 客户端层/扩展/并发客户端/示例/测试未改（per-call 重载已就绪，回退逻辑在引擎层）。
  - README 超时小节重写为三机制：CancellationToken（取消）+ per-call timeout（覆盖）+ engine.ReadWriteTimeout/ConnectTimeout（默认）。用法示例加 `engine.ConnectTimeout=3000; engine.ReadWriteTimeout=2000;`。
- 行为：读写 `effective = timeout>0?timeout:ReadWriteTimeout`，`<=0` 不限制仅 ct；`>0` OR 链接 ct，超时→TimeoutException、ct→OperationCanceledException。连接同理用 ConnectTimeout。沿用"不关 socket、不打断在途发送、迟到响应丢弃"。
- 验证：`dotnet build` 0 警告/0 错误；`dotnet test` 58 通过。
- 当前超时 API 全貌：`engine.ConnectTimeout`/`engine.ReadWriteTimeout` 设默认；`client.ReadXxx(..., cts.Token)` 回退 ReadWriteTimeout；`client.ReadXxx(..., 2000, cts.Token)` per-call 覆盖；`engine.ConnectAsync()` 受 ConnectTimeout 约束。
